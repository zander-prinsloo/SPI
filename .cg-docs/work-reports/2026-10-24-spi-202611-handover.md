**Defect.** The child-mortality (UN IGME) and labour force (ILO) readers
matched countries by exact name against `01_raw_data/metadata/iso_codes.csv`.
Every name that did not match was dropped without a message, and the economy
scored 0:

- **Child mortality, every published release**: the Netherlands ("Netherlands
  (Kingdom of the)"), Türkiye ("Republic of Türkiye") and Kosovo (IGME code
  `RKS`).
- **Labour force, every published release**: Congo, Dem. Rep., Côte
  d'Ivoire, Hong Kong SAR, Macao SAR, West Bank and Gaza, Türkiye and Kosovo.
- **Labour force, new in the 2026 ILO files**: ILO renamed Bolivia, Cabo
  Verde, Iran, Micronesia, Nauru ("Naoero") and Venezuela. Without E6 their
  LFP scores fall to 0 for 2010-2025: 79 false downward revisions, which the
  pre-E6 attribution mislabelled "source update". Examples: Iran -4.0 and
  Cabo Verde -4.0 overall SPI points in 2024.

No wrong match was found in either reader, only dropped economies.

**Fix** (in `R/dim1_5.R`):

- **IGME** is matched on its own ISO3 code (`REF_AREA`) through
  `unigme_area_codes()`, with one documented alias, `RKS` to `XKX`

  AREA CODES NOT RECOGNISED". The old hard-coded Côte d'Ivoire patch is no
  longer needed.
- **ILO** is matched through `iso_codes.csv` plus a recorded crosswalk, via
  `ilo_area_lookup()` and `.ilo_match_areas()`. Any name that is neither
  matched nor recorded as a non-economy stops the run with "ILO AREA NAMES
  NOT RECOGNISED". The lookup is validated:
  - no crosswalk row conflicts with `iso_codes.csv`;
  - every crosswalk code is an SPI economy;
  - no exclusion names an `iso_codes.csv` area.
- **Recorded aggregates are dropped before the join**, which removes the
  former many-to-many warning. That warning was harmless: it only joined
  NA-coded rows, which the reader later dropped.
- **Config files**:
  - `config/ilo_area_crosswalk.csv`: 18 rows, covering the 2025 and 2026
    spellings and including Kosovo (ILO `KOS`) and the Channel Islands (ILO
    `CHA`).
  - `config/ilo_area_exclusions.csv`: 91 rows, 87 ILO aggregates and 4
    non-economies.
  - Both are declared in `config/params.R` and tracked by the new file
    target `ilo_area_names_files`, which feeds `dim1_5`.

### 2.5 Databank aggregates summed in a fixed order (code done)

**Defect.** `build_databank()` reads `SPI_index.csv`, which is sorted by the
overall score, and computes `round(mean(value), 2)` per group in that row
order. About 20 of roughly 77,000 aggregate values sit exactly on a rounding
boundary (for example 0.455), and the floating-point sum lands on either
side of it depending on the order. Any change that reorders countries
therefore moves aggregates of unrelated series by 0.01. E6 did exactly this
(Latin America & Caribbean, 2018, `SPI.D2.2.Terms.of.use`, 0.13 to 0.14).

The December ODIN swap reorders almost every country. The release diff,
which allows only ODIN-dependent series to change, would then very likely
block promotion with a false alarm. The earlier rehearsal did not catch this
because it perturbed only 10 economies.

**Fix.** New `aggregate_databank()` in `R/databank.R` sums the members in
ISO3 order. `tests/testthat/test-databank-aggregates.R` (2 tests, 7
expectations) failed on the behaviour-preserving refactor and passes with
the fix.

**Effect.** About 18-21 aggregate values per run move by ±0.01 relative to
the legacy summation order. Country values are unchanged. Aggregate rows are
already excluded from the vintage comparisons (E3).
